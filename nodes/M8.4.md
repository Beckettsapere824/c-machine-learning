## Content / 内容

The basic training loop is:
```
for epoch in 1 … E
    for each mini-batch (X_b, y_b)
        zero gradients
        forward → loss
        backward → gradients
        update parameters with an optimiser (SGD, Adam, …)
```
Key practical ingredients:
- **Mini-batching** reduces gradient noise while exploiting vectorisation;
- **Learning-rate schedules** (step decay, cosine, warm-up) improve final accuracy;
- **Initialisation** (He, Xavier) keeps activation variances stable across layers;
- **Regularisation** (weight decay, dropout, data augmentation) controls overfitting;
- Monitoring train/validation curves detects under- or over-fitting early.

训练循环 = 前向 + 反向 + 参数更新。小批量、学习率调度、合理初始化与正则化是让深度网络真正可训练的关键工程细节。

## Tiny Python sketch
```python
opt = torch.optim.Adam(model.parameters(), lr=1e-3)
for epoch in range(E):
    for Xb, yb in loader:
        opt.zero_grad()
        loss = criterion(model(Xb), yb)
        loss.backward()
        opt.step()
```

## Practice / 练习

Why is it dangerous to use a learning rate that is constant and large for the entire training run of a deep network?

<details>
<summary>Solution sketch</summary>

Early on a large step helps escape flat regions; later the same step size causes the iterates to oscillate around a sharp minimum and can even diverge. Schedules that decay the learning rate resolve the conflict.

</details>
